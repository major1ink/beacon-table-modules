# Модули для Beacon Table

Отдельный репозиторий с модулями контента для [Beacon Table](https://github.com/major1ink/Beacon-Table):
игровые системы и карточки к ним. Контент выходит в своём ритме, без обновления
программы: правка правила, нового монстра или заклинания — это новая версия модуля,
а не нового релиза программы.

## Что здесь лежит

| Модуль | Тип | Что внутри |
|---|---|---|
| `dnd5e-2014` | система | схемы листа и карточек, правила боя, монеты и вес, состояния SRD 5.1, импортёры |
| `dnd5e-2024` | система | то же для редакции 2024, состояния SRD 5.2 |
| `dnd5e-2024-srd` | контент | существа, заклинания, предметы и справочник SRD 5.2 (требует `dnd5e-2024`) |

Раскладка модуля (папка в `modules/`):

```
module.json      манифест: id, версия, правила системы, совместимость
CHANGELOG.md     записи об изменениях, последняя версия сверху
LICENSE, NOTICE  лицензия и обязательная атрибуция
schemas/         схемы листа и карточек (у системных модулей)
bestiary/ spells/ items/ references/ conditions/   карточки, по файлу на карточку
assets/          картинки карточек
```

Карточка — тот же JSON, что у карточки библиотеки в программе, без `id` и `updatedAt`.
Имя файла — `slug` карточки (латиница и дефисы): по нему строятся id и ссылки
(`sys-<slug>` у модулей D&D с `legacyIds`). **`slug` вечен:** удалить или переименовать
карточку можно только с повышением major-версии модуля.

## Как выпустить новую версию

1. Поправить карточки или схемы.
2. Поднять `version` в `module.json` и добавить сверху `CHANGELOG.md` запись
   `## 1.1.0 — 2026-10-15` с текстом изменений (patch — правки текстов, minor — новые
   карточки, major — удалён или переименован `slug`).
3. `task validate` — проверка тем же кодом, что и установка в программе.
4. Запушить в `main`: CI заметит, что тега `<id>/v<версия>` ещё нет, соберёт только
   этот модуль и создаст выпуск.

## Проверка и сборка локально

Нужны Go и [Task](https://taskfile.dev); основной репозиторий Beacon Table лежит рядом
(`../Beacon-Table`), из него собирается утилита `btmod`.

```bash
task validate                      # все модули
task validate MODULE=dnd5e-2024    # один модуль
task pack MODULE=dnd5e-2024        # dist/dnd5e-2024-1.0.0.btmod, .sha256, .summary.json
task index                         # dist/index.json
```

## Публикация (один раз)

1. Создать на GitHub публичный репозиторий `major1ink/beacon-table-modules` и запушить в него `main`.
2. Settings → Secrets and variables → Actions → **Variables**: добавить `BEACON_APP_REF` — тег или
   ветка основного репозитория, из которой собирается `btmod` (до выхода Beacon Table 0.9.0 — ветка
   с утилитой, после — тег `v0.9.0`). Без переменной берётся `main`.
3. Settings → Actions → General → Workflow permissions — *Read and write permissions*.
4. Первый пуш в `main` создаст выпуски всех трёх модулей (`dnd5e-2014/v1.0.0` и так далее) и ветку
   `gh-pages` с `index.json`.
5. Settings → Pages → *Deploy from a branch* → `gh-pages` / `(root)`. Каталог модулей
   будет по адресу `https://major1ink.github.io/beacon-table-modules/index.json`.

Дальше CI работает сам: `validate.yml` проверяет каждый пуш и pull request, `release.yml` на пуше в
`main` выпускает модули с поднятой версией (`scripts/release.sh`; локально — `DRY_RUN=1`,
ничего не создаёт). Офлайн модуль скачивается со страницы выпусков и ставится в программе кнопкой
«Из файла».
